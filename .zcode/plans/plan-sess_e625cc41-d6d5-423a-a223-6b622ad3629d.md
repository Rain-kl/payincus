## 目标

搭建**前端集中 Token 层**主题管理系统：所有颜色色值只有一个定义源（`client/src/styles/theme.css`），组件与全局样式一律通过 token 引用，禁止再在组件里写死十六进制色。保留 light/dark 双主题。不涉及后端/DB/管理后台。

## 背景（已探明）

- 当前色值定义分散在 3 处：`main.css` 的 `:root`(暗)/`.light`(亮) 语义变量、`kawaii-cloud.css` 的 `--kawaii-*`、`tailwind.config.js` 的调色板——需收敛为单一来源。
- 组件内硬编码 hex 346 处 / 31 个文件，其中约 13% 能直接映射现有 token；最大重复块是 HelpView + HelpManageView 的 GitHub markdown 语法主题与 md-alert（约 50 行两处重复）。
- 守卫测试不锁颜色 class（`test:frontend-route-guards` 只断言路由/表格布局 class/段落注释标记），改颜色安全；`test:frontend-i18n-keys` 只要不加新 i18n key 就安全。
- 娱乐模块彩色、Help 分类色（后端下发数据）、第三方品牌色（Google/GitHub）属豁免区。

| 语义 token | 浅色 | 暗色 | 说明 |

| `--bg-surface`（卡片/白底） | `#FFFFFF` | `#1f1d1b` | 弹窗、卡片 |
| `--bg-surface-soft` | `#FBF9F8` | `#282522` | 次级背景 |
| `--border-color` | `#E4E3E0` | `#2C2A29` | 常规边框（现有 #e0dfdd 收敛为此值） |

## 实施步骤

### A. 建立单一 Token 来源
1. 新建 `client/src/styles/theme.css`：包含全部语义变量（`:root` + `.light` 两套），上表 9 色落地，其余沿用现值。**这是唯一允许出现 hex 色值的 CSS 文件**。
2. `main.css`：
   - 删除自身 `@layer base` 里的 `:root`/`.light` 变量块（12-93 行），改为顶部 `@import './theme.css'`。
   - 全局组件类（`.btn-primary`/`.btn-secondary`/`.btn-ghost`/输入框/滚动条/::selection 等）里散落的 `#161513`/`#2c2a28`/`#ffffff` 等改为 `var(--xxx)` token。
3. `kawaii-cloud.css`：`--kawaii-*`（9-43 行）改为**引用**新 token（`--kawaii-bg: var(--bg-primary)`、`--kawaii-surface: var(--bg-surface)`、`--kawaii-primary: var(--accent)`、`--kawaii-text: var(--text-primary)` 等），不再写 hex；shell 作用域映射保持不变。`kawaii-cloud.css` 属于「渐进改造」，只改变量定义，不动装饰类。
4. `tailwind.config.js`：
   - `primary` ramp 色值与 theme.css 同步（加注释声明同源）；`accent` 已用 `var(--accent)` 保持。
   - 顺手为选中态新增 `nav-active: 'var(--nav-active)'`、`surface: 'var(--bg-surface)'` 等映射 token（静态色阶保持）。
5. `theme.ts`：meta theme-color 的 `#F6F4F3`/`#0a0a0a` 改为读 `--bg-primary`（getComputedStyle）或同步新 token，不再硬编码。

### B. 布局/全局组件替换硬编码色（用户最直接可见）
6. `AppLayout.vue`（29 处）：顶栏 `#2c2a28`/`#393632`/`#ffffff` `!important` 覆盖、footer `#F5F4F2`/`#e5e4e0`/`#66615e`/`#161513` 全部替换为 `var(--topbar-bg)`/`var(--border-color)`/`var(--bg-surface)` 等。
7. `SideNav.vue`（19 处）：`border-[#2c2a28]`、品牌条 `#393632/#1f1d1b`、搜索框 `#f5f5f4/#161513/#282522/#f4f4f3`、激活态 `#0b5cad/#4593de`（→ `var(--nav-active)`）全部替换。
8. 同类可映射文件：`TermsOfServiceModal.vue`（`#141414/#ededed/#18181b` 等 markdown 中性色）、`InstanceDetailView.vue`、`LoginView`/`AdminLoginView`（品牌色/错误色）、`TrafficStats.vue` 图表色抽成 token 常量。

### C. 收敛重复大块
9. 把 HelpView + HelpManageView 重复的 **GitHub markdown 语法主题**（约 50 行 ×2）与 **md-alert 四态样式**抽为共享 CSS 变量（新增 `--md-*` 或归入 markdown token 块），两个文件改用变量，消除重复。响应式类名与段落注释标记不触碰。

### D. 豁免清单（明示「允许保留」的区域）
- 娱乐游戏化模块（EntertainmentView/CheckinModal/BadgeReward 的彩虹/金色/奖品色）——AGENTS.md 明确保留。
- Help 分类颜色（`#6b7280` 等后端下发数据）、第三方品牌符号色（Google/GitHub 四色）。
- 数据可视化图表色若不便 token 化，抽为共享常量文件（`client/src/theme/chart-colors.ts`）收纳，不算「组件内散落」。

### E. 守卫（把「禁止组件指定颜色」固化为验收线）
10. 新建 `server/scripts/test-frontend-color-tokens.ts` + `server/package.json` 的 `test:frontend-color-tokens`：
    - 全局扫描 `client/src/**/*.vue/.ts/.css`，禁止出现 `#[0-9a-fA-F]{6}` 与 tailwind arbitrary `bg-[#..]` 类，**白名单**：`theme.css`、娱乐模块相关文件、Help 分类色、`theme/chart-colors.ts`、第三方品牌色所在文件。
    - 挂进 `pnpm test` 链条（root package.json test 命令追加一行）。
11. 跑 `pnpm --filter client type-check` + `test:frontend-route-guards` + `test:frontend-i18n-keys` + `test:frontend-color-tokens` + `pnpm build:client`（双端 build）。

### F. 提交
12. 按仓库规矩提交（只含本次文件，不 push），提交信息按 Conventional Commits。

## 风险与边界

- **守卫安全**：已确认颜色 class 不被守卫锁定；唯一注意不改表格三个锁定 class 与段注释标记（B/C 步骤不涉及）。
- **双主题**：保留 light/dark/system，两套色板都在 theme.css 内。
- **不动**：后端、DB、路由行为、支付/实例等业务逻辑。
- **视觉微调**：按钮色从 #0b5cad→#295BA7、顶栏 #393632→#383632、边框 #e0dfdd→#E4E3E0、侧栏选中从蓝→#161513，属需求要求的视觉变更，计划内。
