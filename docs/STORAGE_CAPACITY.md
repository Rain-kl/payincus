# 实例存储容量判定

`hosts.storage_size` 是节点初始化时的存储大小参数，旧节点常保留默认值 60 GB。
它不再用于售罄、开通、克隆和扩容判断，也不会因读取存储状态而被自动修改。
宿主系统分区的使用率与实例存储池的容量分别展示。

容量统一由 `server/src/lib/storage-capacity.ts` 读取 Incus 管理 API，兼容现有 Agent
反向隧道和直接 mTLS 连接，不需要升级 Agent 或修改数据库结构。

- 只考虑已登记为 `instance_data` 的系统盘池。这里的“系统盘”指实例系统盘，不是宿主 `/` 分区。
- 套餐指定池时，只检查该池；池不存在或容量不足时不转投另一个池。
- 未指定时，在有足够可分配容量的池中选择剩余容量最大的池。
- 创建时在宿主行锁内复查容量、预占资源，并在同一事务中保存实例的池名；交付时不再随机选池。
- 扩容检查实例原来的池；旧实例未登记池名时，读取 Incus 的根盘设备定位实际池，不猜测或更换池。

可分配空间按实际空闲空间，扣除已承诺但尚未使用的实例容量、未落到实例记录的预占，
以及安全余量。余量为总容量的 1%，最低 1 GiB、最高 10 GiB。
若驱动无法报告单个根卷的实际占用，该实例按完整逻辑容量预留，结果会更保守。
卷用量抵扣不能超过池的实际已用空间，避免压缩、稀疏卷等指标差异放大可分配空间。

ZFS 按底层池、LVM 按卷组归并容量。Incus 没有提供目录所在文件系统的 ID，
因此同一宿主的 DIR/Btrfs 目录池保守地视为可能共享空间：不简单累加总容量，
跨目录的逻辑预留共同消耗预算。这避免同一数据盘重复售卖，但独立数据盘上的目录池
可能被低估；此时不要把目录池显示值相加后当成可承诺容量。

容量读数缓存 5 秒，同宿主并发查询复用一次读取。容量请求带取消信号，连接和整个
采集过程有时限；失败、无效或过期读数不会回退到旧的 60 GB，也不会视为无限容量。
实际外部写入仍可能在检查后改变空闲空间，Incus 交付失败继续使用既有补偿流程。

可用节点接口返回 `unavailableHosts`，区分 `disk_full`、`storage_unavailable`、
`storage_pool_missing`；前端另行显示接口请求失败，避免一律提示 CPU/内存不足。

## 验证

纯计算测试：`pnpm --filter server test:storage-capacity`。

数据库与真实路由测试使用明确指定、数据库名以 `_test` 结尾的本地隔离 PostgreSQL：

```sh
RUN_STORAGE_DB_TESTS=1 pnpm --filter server test:storage-capacity
```

测试使用真实 PostgreSQL 事务与 Fastify 路由，Incus 读数使用受控测试响应；覆盖旧 60 GB
节点、LXC/KVM、满盘、不可达、无效绑定、多池选择、目录池重复计数、扩容与并发申请。
本地测试通过不等于线上交付验收；上线后还应在目标节点实际创建、扩容并验证失败回滚。
