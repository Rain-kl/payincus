# 存储登记、心跳与容量分配

本次实现以 `canary` 为开发基线；节点仍基于 Incus `v7.0.2` LTS。代码和本地验证不表示已经发布或部署。

## 数据流

1. 管理员创建、关联或导入池，成功后将池名、驱动、来源配置、用途和描述保存到 `storage_pools`。已有加密建池流程仍先托管密钥，再写节点，最后登记已核验的池。
2. Incus 内置采集器通过本机 Unix socket 调用正式 API，连接器将存储、硬盘、加密状态随已签名心跳推送控制端。默认周期仍为 10 秒。没有新增节点监听端口。
3. 控制端只更新已经登记的池，保存状态、总容量、实际占用、采样时间与经过筛选的遥测。完整清单缺池时标记 `missing`；读取失败标记 `unavailable`；均保留上次容量。截断清单不会把未列出的池当作删除。
4. 列表、详情、存储加密 GET、套餐库存、候选节点与最终资源预占均读数据库。移除了容量的内存快照和按请求拉取节点/卷资源的逻辑。无网络读取回退。
5. 验证、连接测试、同步按钮向现有认证 WebSocket 发 `HEARTBEAT=0x0b` 通知，立即返回 HTTP 202。节点将请求合并为至多一个待执行心跳，使用正常 HMAC 上报链路写回；202 表示通知已排队，不表示采集已经完成。离线/缺少 `heartbeat-trigger-v1` 能力返回 409。创建和存储写操作完成后也通知立即上报。

即使 incusd 停机或报告接口失败，连接器也会上报 `incus.available=false` 和存储不可用，不中断通信；本地检查最多使用总请求预算中的 45 秒，为故障心跳留出传输时间。缺失的 Caddy 采样不会被当成卸载成功。

首次有效心跳负责完成节点安装记录和默认控制端证书路径；保留已有证书和维护状态。硬盘、网络等原生硬件信息保存在 `host_agents.last_report.resources`，公网 IPv6 自动发现改用心跳信息。原生硬盘采集失败时保留上次硬盘清单，同时上报 `storageAvailable=false`，不把缺失数据伪装成空硬盘清单。

## 容量口径

- 「实例已分配」为节点所有未删除实例的 `disk` 合计，单位 MiB，包括创建中、停机和业务封停实例。
- 「存储池总容量」为数据库中所有 `instance_data` 池的 `total_bytes` 合计，转换为 MiB；不是安装时的 `storage_size`、宿主机裸盘总容量或请求失败时的默认值。
- 总容量是登记池的逻辑容量之和；别名池和稀疏文件不代表新增独立物理空间。分配仍对共享底层空间做约束。
- 新实例依次检查：节点在线、未锁定且服务可用；目标系统盘池状态为 `ready`、采样有效；目标池的剩余容量足以预占。
- 套餐有明确 `storagePoolName` 时只检查该池。名称失效、用途变更、锁盘或容量不足均不借用其它池。未指定池的绑定可选择可用容量最多的系统盘池；不使用节点容量总和创建实例。
- 可分配量受池逻辑容量减已承诺额度、实际剩余空间、共享 ZFS/VG/文件系统，以及已有预占限制；保留原有容量余量。DIR/Btrfs 使用节点上报的文件系统身份区分独立磁盘，避免把不相关磁盘的实例合并扣减。
- ZFS Loop 上报真实文件大小及底层文件系统可用量；同一文件系统上的稀疏文件池共享实际可用空间约束。为避免超卖，底层检查保守地扣除完整逻辑承诺，实际利用率可能低于允许超卖的配置。
- 心跳超过 `max(120 秒, 3 × 配置周期)` 后禁止新分配，但列表仍保留上次容量。采样时间最多允许领先控制端 30 秒、滞后 120 秒；节点和控制端应同步系统时钟。
- 通过采样时间、池记录 ID 和条件更新阻止乱序报告覆盖，以及删除重建同名池后旧报告回填。不自动重建被删除的控制端记录。已有实例缺失根池名时由实例心跳补齐，容量检查不再现场访问实例元数据。

数据库操作同时修正了存储用途 `purpose` 漏写；`default` 也必须有实际登记。已记录根池被移除后，重建逻辑不会静默改选另一池。

## ZFS Loop 扩容

控制端默认加密 Loop 池使用 `池名/incus` 数据集绑定 Incus，文件可能位于自定义目录。上游原生 `PATCH .../storage-pools/:name` 的 `size` 只支持 Incus 自己创建的默认 Loop 文件，无法定位这种外部数据集的文件；这是该路径扩容报错的原因。

新增能力 `payincus_storage_pool_resize_v1` 和 `POST /1.0/payincus/storage/resize`，参数为 `{dataset,sizeGiB}`。控制端先核对真实池配置和能力，再选择原生 PATCH 或该扩展。扩展要求已认证的远程 mTLS 控制端，校验注册数据集 GUID、父池身份标记、在线的单一普通文件 vdev，持有节点存储写互斥。根据 `zpool status -P` 定位实际文件，不接受浏览器传入文件路径，不猜默认目录。

文件使用 `truncate` 增大，新增区间保持稀疏；执行 `zpool online -e` 让 ZFS 识别新增空间。不缩容、不增加 vdev、不改加密密钥。若文件已增大而 ZFS 扩展失败，可重试同一目标大小；不回缩文件。大小为整数 GiB/TiB，最大 65536 GiB。物理盘、多 vdev 和不属于节点管理的外部池不走此扩展。创建时预分配的池在扩容时新增区间同样按稀疏方式增长。

原生 Incus Loop 更新额外拒绝非法大小和缩容，避免误截断 vdev。控制端容量只在后续心跳确认后更新，不把请求的目标大小当成实际可用容量。

## 接线与验证

- 节点：`internal/server/payincus/report/{storage,incus,report}.go`，`security/storage_resize.go`，`cmd/payincus-agent/main.go`，`tunnel/{framing,tunnel}.go`。
- 原生 API：本地 `GET /1.0/resources`、`GET /1.0/storage-pools?recursion=1`、`GET /1.0/storage-pools/:name/resources`，实例清单中的 `expanded_devices`；加密清单复用 `/1.0/payincus/storage`。
- 控制端：`services/agent-storage-report.ts`、`lib/storage-capacity.ts`、`lib/storage/{read-model,resize,session}.ts`；schema 变更为 `20261028080000_storage_heartbeat`。
- 新增 `test:storage-telemetry` 和 `test:storage-telemetry:db`；后者只允许本地以 `_test` 结尾的临时数据库。覆盖纯数据库查询、通知能力/权限、乱序/失败/删后重建、套餐绑定、独立磁盘、共享稀疏 backing、用途落库与离线容量保留；实际签名心跳路由还覆盖首次安装记录/证书路径、架构、硬盘失败保留和锁定状态。
- `RUN_STORAGE_DB_TESTS=1 test:storage-capacity` 验证库存、API 候选、扩容额度及并发预占；已有加密、锁盘、恢复、节点安全和前端守卫回归通过。
- 节点单元/HTTP 合约、原生存储驱动缩容保护回归与 race 检测通过；隔离 QEMU 中真实 ZFS 验证 1 GiB → 2 GiB 稀疏加密池扩容、ZFS 容量增长、原数据可读、重复请求和缩容拒绝。未接入用户生产节点。

上线需要配套更新 Incus 节点包并应用控制端 schema。旧节点不具备存储心跳或通知能力时，控制端不恢复主动拉取兼容；首个有效心跳前池显示等待上报且不可分配。
