# 共享出口策略

## 模型

代理目录只保存独立代理节点与加密凭据。出口策略 `EgressProfile` 保存当前选择的代理节点、顺序、负载均衡/故障转移/最低延迟方式、检测 URL/间隔和内网规则，以及允许使用的宿主范围。策略原地编辑，不存在策略版本、发布版本接口或历史快照。

套餐引用 `egressProfileId`，创建实例时只绑定同一个策略身份；不复制策略内容。节点的网络出口也引用同一个目录中的策略，节点页面不再创建独立代理组合。套餐与实例可以选择沿用节点出口 (`host`)、直连 (`direct`)、共享策略 (`profile`)。

`Package.egressProfileId`、`Instance.egressProfileId`、`InstanceEgressAttachment.profileId` 和 `HostNetworkPolicy.egressProfileId` 使用外键引用策略，策略仍被引用时不可删除。代理节点仍被任意策略使用时同样不可删除。请求按管理员/宿主权限验证，用户只能看到策略名称与自己获授权的宿主，不返回代理凭据。

## 策略变更与节点执行

保存策略在 PostgreSQL 事务内串行化引用、检查代理及宿主存在，查找引用它的节点、套餐宿主、实例与运行绑定。不能从授权范围移除仍被引用的宿主。事务更新当前策略，并递增受本次变更影响宿主的投递序号；受影响范围包含本次提交的授权宿主、被撤销授权的宿主，以及仍被引用的宿主。返回 202 后通过现有在线隧道异步下发。

每次组装网络指令都读取当前策略和当前代理凭据，出口组 key 为 `p<策略ID>`。除运行绑定所需的组外，宿主已获授权的策略也会预置出口组：授权即在该宿主准备 xray 运行环境，不必等到第一次创建实例才补齐。绑定所需的组是硬性要求，缺失或不可用会直接报错；授权预置是尽力而为，容量或解析失败只跳过该组，不影响绑定。宿主投递序号只用于确认/去重/重试，不是策略版本，也不提供历史查询。在线节点立即应用；离线节点保留数据库中的待同步意图，心跳或隧道重连时重试。节点失败时保留待同步/错误状态，不谎报成功。

例如套餐 A 引用策略 P，已有实例 I 同样引用 P。代理 N1 故障时编辑 P，把 N1 换为 N2；下次指令重新解析 P 并应用 N2，I 无需重建或修改套餐。策略对新连接生效，既有连接可能保留原路径；故障期间阻断，不自动退回宿主直出。

套餐绑定策略的 ID 若改为另一个策略，影响后续新实例；已有实例持有原共享策略 ID。需要改变已有实例出口时编辑被引用的策略，避免把两种管理动作混为历史快照。

## 管理界面

代理页面提供「代理节点」和「出口策略」两个 tab。

- 默认节点表格：多选、名称、协议、地址、延迟、操作；添加按钮打开抽屉，可导入订阅、分享链接或配置文件。
- 执行检测的宿主下拉框、检测按钮与添加按钮位于表格标题行。多个节点按 10 个一批探测，结果直接显示在右侧延迟列；页面离开会取消请求，不保存测试结果。
- 策略 tab：创建/编辑抽屉，选择多个代理并排序，配置故障转移、负载均衡或最低延迟，以及检测及内网设置。没有版本/历史界面。
- 节点配置页面：选择当前全局策略；套餐页面同样选择共享策略，不选择历史版本。

节点 TUI 的 Xray 菜单调用本机 Incus API，支持查看已分配代理、测试、重启、日志和重新配置。重新配置重建托管 runtime，保留控制端意图和流量阻断 guard，失败后不会退回宿主直出。重建准备环境与代理行为无关：本节点尚未下发任何策略时，重新配置仍会重建核心二进制与网关命名空间并成功返回，只是不接管流量；此时重启仍按无策略拒绝。

## 接口与验证

- `GET /api/egress/profiles`：按调用者权限返回当前策略。
- `POST /api/admin/egress-profiles`：创建。
- `PUT /api/admin/egress-profiles/:id`：原地编辑并异步下发。
- `DELETE /api/admin/egress-profiles/:id`：拒绝删除被引用的策略。
- `PUT /api/hosts/:id/network-policy/egress`：只接受 egressMode / egressProfileId 与宿主投递并发检查。
- `GET /api/instances/:id/egress`：当前绑定策略及节点确认状态，不返回版本。

实现主要位于 `server/src/lib/egress/{package,sync,attachments,realtime}.ts`、`routes/{egress,egress-profiles}.ts`、Prisma schema 与客户端对应类型。测试 `test-package-egress.ts` 包含纯逻辑及专用 PostgreSQL API 集成，`test-egress.ts` 覆盖策略验证、下发、探测及错误；前端 route/i18n/color 守卫、类型与双端 build 一并执行。

本变更以新部署契约开发，不提供旧节点、旧策略版本或套餐数据的兼容迁移包。正常数据库 schema 迁移保留在 Prisma migrations 中，不能把旧字段名继续作为运行时 fallback。
