# 节点 CLI 安全模式、ZFS 密钥托管与恢复

本功能需配合 Rain-kl/incus 的 `payincus_security_v1` 扩展，基于正式 Incus 7.0.2 LTS。功能默认关闭，可用于没有 ZFS 的 DIR 节点。它用于记录常规取数操作、停止容器与限制恢复，不能防御完整宿主 root 读取运行中明文/密钥或修改程序。

## 配置顺序

1. 更新控制端并按现有升级流程执行 `20261026000000_add_node_security` 数据库迁移；数据库和现有 `ENCRYPTION_KEY` 分开备份。托管要求独立配置的高熵主密钥至少 32 字符；建议随机 32 字节以上。不使用 JWT 签名密钥作为回退。
2. 安装支持该扩展的集成 deb，启动 incusd 和连接 Agent，按现有流程完成 Agent HMAC 身份和 Panel mTLS 客户端证书信任。Agent 凭据不能自动获得存储密钥。
3. 通过可信终端运行 `incus-tui`，核对状态区的“节点证书 SHA256”。在管理端“节点 → 运维 → 节点安全模式 → 核对证书指纹”手工保存。直连和反向隧道均先校验此指纹，再发送 HTTP 请求；未配置或不匹配时不会发送解锁密钥。更换节点服务端证书后必须重新核对，不自动采用网络返回的新指纹。
4. 需要 ZFS 时，在 TUI 显式安装依赖、准备专用磁盘/分区或测试文件池。默认一键初始化依然使用 DIR，不自动迁移已有容器。Debian 13 / Ubuntu 24.04 为已支持目标；Secure Boot、特殊内核和自定义 APT 源可能需要人工处理。
5. TUI 创建加密根时生成 64 位十六进制密钥，在控制端保存“节点 + 数据集 + 密钥”。控制端只回显 SHA256 指纹；将它复制回 TUI 核对后再确认创建。节点记录 ZFS GUID、加密根和密钥指纹，明文不写密钥文件。已有加密根必须提供现有密钥注册，不能从 ZFS 导出原始密钥；不支持原地加密已有明文数据。
6. TUI 将已注册加密根绑定为 Incus ZFS 存储池。管理员自行完成 profile/实例存储选择或迁移；本功能不修改已有 DIR 实例。
7. 确认影响范围后，在控制端开启关键命令安全模式。该开关不要求存在加密存储。

## 触发与恢复

受管 Linux `incus` CLI 全部调用会记录分类、UID/PID、时间、是否关键及是否拒绝，不记录完整参数、命令载荷或 stdin。普通查询和 help/version 只审计；exec、shell、console、文件访问、导出/发布/复制/移动、危险配置及启动/恢复等命令触发。未知别名按敏感操作处理，TUI 使用原生 Unix API，不走受安全模式监控的 CLI。

触发时先持久化统一 API 锁定，再停止本节点全部 LXC 容器；停止核验后，对已注册 ZFS 根卸载文件系统、卸载密钥并核验。连接 Agent 与 incusd 保持运行，独立报告每项结果。没有 ZFS 时明确显示附加存储锁定不适用，不能宣称 DIR 数据被加密。普通 CLI 和受限节点 API 返回 `Failed to begin transaction: sql: database disk image is malformed (11)`，管理端保留真实结果。

告警进入控制端管理日志；独立 HMAC 上报通常在本地检查后 2 秒内发起，实际送达受网络/队列影响。只有事务提交后才 ACK 并删除节点事件，断网时重试，不能保证断网期间实时远程报警。每批 128 条、本地上限 2048 条，队列满时拒绝新的受管 CLI 调用；节点上报时控制端清理 30 天前记录（离线期间不主动清理），页面显示最近 100 条。

恢复必须由控制端管理员确认：

1. 检查告警与每项停止/卸载结果，处理残留进程或 busy 存储。失败后可再次“立即锁定”重试；失败不自动放行 API。
2. 对每个已注册加密根点击“加载密钥”，或经控制端“领取密钥”后在 TUI 隐藏输入。加载只解除存储加密锁定，不解除节点 API 锁定。
3. 等停止核验完成，在控制端“批准恢复”。节点要求当前 revision、全部注册根 GUID/加密属性匹配、密钥已加载；过期请求或本地 Unix socket 请求不会恢复。
4. 批准恢复后立即返回后台任务编号；任务等待原生异步启动操作完成，恢复锁定前运行的容器；原本停止的容器保持停止。节点在停止前持久化项目、名称、UUID 和冻结状态，恢复成功后逐项确认，失败项可再次点击批准恢复重试。不会启动同名替换实例，业务封停、已删除或已过期的实例不自动启动。

关闭安全模式、Agent 重连与节点重启均不清除锁定；已启用安全模式或注册加密根的节点重启也需控制端批准。不要把 OS、Agent 配置、Incus 管理数据库放进需要本链路解锁的数据集。此版本聚焦 LXC，其他进程/虚拟机占用受保护池时可能导致 ZFS 卸载失败。

## 托管与权限

专用 AES-256-GCM envelope 使用随机 96 位 IV，HKDF 从现有 `ENCRYPTION_KEY` 派生独立用途密钥，AAD 绑定 hostId/dataset/version。数据库存密文，不存明文。格式错误、错误主密钥、篡改及身份不匹配一律拒绝，不继承旧工具函数“解密失败返回原值”的兼容行为，无外部 KMS 依赖。

全部新增管理接口要求 Web 管理员权限；普通用户、节点 Agent 无权领取或恢复。领取/加载密钥前必须将敏感操作审计持久化；审计失败不提供密钥。响应禁止缓存，前端关闭抽屉/切换节点时清除密钥显示。底层节点恢复复用已有 Incus 远程 mTLS 管理身份，持有其它受信任管理员私钥的人也有相同权限，不是硬件认证的唯一控制端。

程序不主动写节点明文密钥文件，不等于密钥不会进入 Go/JS 内存副本、宿主 swap/core dump、终端录屏或剪贴板历史。管理员领取的原始密钥没有临时验证码的过期属性；持有者可绕过程序解锁存储。本次未实现在线主密钥轮换、ZFS 换钥或密钥删除，不能直接更换 `ENCRYPTION_KEY`；丢失主密钥会失去托管数据的解密能力。保留原密钥备份，轮换必须设计迁移并验证后另行执行。

## API 与测试

| 接口 | 契约与覆盖 |
| --- | --- |
| GET `/api/admin/hosts/:hostId/node-security` | 管理员认证、在线状态或上次报告、指纹、密钥元数据、100 条审计；不返回托管密文/明文 |
| POST 同路径 `/identity` | 管理员手工录入服务端证书 SHA256，不能由节点报告覆盖 |
| POST `/policy`、`/lock`、`/recover` | 指纹校验的原生 mTLS，能力探测，revision/错误传播，控制端操作日志 |
| POST `/keys` | 严格 hex 密钥、身份绑定加密入库、同指纹幂等核验、拒绝覆盖不同密钥 |
| POST `/keys/reveal`、`/keys/unlock` | 管理员权限、先持久审计、no-store、严格解密；解锁不自动批准恢复 |
| POST `/api/agent/security-report` | 真实 body hash、HMAC、时间戳、nonce；单节点事务锁、去重/ACK、防旧 revision 覆盖及远程告警 |

`server/scripts/test-node-security.ts` 覆盖密钥 envelope/篡改/身份及报告脱敏；`test-node-security-routes.ts` 使用真实 Fastify 注入验证权限、领取前审计及错误处理；`test-node-security-transport.ts` 使用真实 TLS 覆盖直连/隧道和错误证书无法接收 HTTP 数据；`test-node-security-db.ts` 在专用 PostgreSQL 库验证事务 ACK、去重、完整 UID 范围、告警、指纹保留与旧报告拒绝。CI 使用独立 PostgreSQL service 执行数据库集成测试。

本地已通过前后端类型检查、相关守卫及双端 build。另在隔离测试库与真实 incusd 联通，验证指纹登记、策略、停止核验、恢复授权和密钥托管/领取；真实 LXC 的安全模式停止、锁定文件 API、重启持续锁定已在 Incus 仓库验证。ZFS 的内核/磁盘验收单独记录在 Incus FEATURES.md。源码测试、发布包 CI、生产部署是不同证据，本次没有操作生产。

## 安全模式状态与自动恢复（2026-10-28）

- 开发基于最新 canary（最终同步至 `4245d12`，保留新增 Incus Web UI）。节点上游基线仍为 Incus v7.0.2 LTS；控制端和节点集成包需配套更新，恢复前探测 `payincus_security_resume_v1`，缺失能力时拒绝执行恢复，不加入旧 Agent 或历史协议回退。
- 用户实例列表、详情和统计返回服务可用状态：节点离线、隧道断开、锁定、心跳过期、缺失 Incus 可用确认或明确报告实例采集不可用时，已交付实例显示 `error`；“运行/停止/错误”筛选及分页计数使用同一规则。待恢复的实例继续显示错误。创建中、业务封停、已删除等业务状态保留；不将外部不可用写成创建失败，不改变退款、计费或资源占用数据。维护标记本身不会停止已有实例，不单独据此判定错误。
- 节点列表及详情通过独立状态报告投影 `locked`，显示“已锁定”；底层连接状态和 Agent 通信不被改写。锁定优先于离线显示，原有隧道及维护处理保留。
- 停机前持久保存运行容器的项目、名称、UUID 和冻结状态；重复锁定和 daemon 重启保留未完成的清单。控制端授权解除锁定后，通过 Incus 7.0.2 原生 GET 实例、GET/PUT state 及 operation wait 恢复，成功核验后 POST `/1.0/payincus/security/resume` 逐项确认。原先停止的实例不启动；被冻结的实例恢复后重新冻结。恢复请求按节点串行，部分失败保留清单，可再次批准恢复，已成功启动项不重复启动。
- 自动恢复不绕过业务封停、删除或到期检查，不启动 UUID 已改变的同名实例。此清单从本功能记录开始生效，不能追溯此前已丢失的停机前状态；已经被销毁的实例也不能自动重建。清单读取/落盘失败仍执行停止与存储处置，并保持锁定、报告清单失败，拒绝宣称自动恢复完成。
- 统一使用“安全模式”名称。最近 CLI 审计仅查询 Incus CLI 命令白名单，最多 100 条；Agent 心跳、状态轮询与恢复 API 不生成 CLI 事件，也不会占用该列表。原生 API 的错误响应继续保持通用内部错误。
- 新增 `test-host-service-status.ts`、`test-node-security-recovery.ts`，并扩展管理路由/节点侧测试：覆盖状态优先级、业务状态隔离、筛选、证书/权限、同名替换、原生异步失败、部分重试、ACK 丢失、冻结恢复、持久清单和非 CLI 轮询不入审计。已通过相关守卫、前后端类型检查和双端 Vue 构建；真实隔离 daemon/mTLS/LXC 验证运行与冻结恢复、停止保持及轮询排除。新增实现和前端定向 lint 无错误；全文件服务端 lint 中 `instances.ts` 的既有空 catch 仍报 `no-empty`，已对原 canary 复核，未借本次改动重构无关代码。未部署生产。


## 批准恢复改为异步任务（2026-10-28）

- POST `/api/admin/hosts/:hostId/node-security/recover` 保留管理员权限、revision 格式和已核对证书的要求；持久化任务后立即返回 HTTP `202` 与 `{ taskId, status: "running" }`，不等待节点解锁、容器启动或冻结完成。节点能力、revision 与存储核验在任务中执行，失败进入任务日志，不能将“已接受”当作“恢复成功”。
- 复用既有 `operation_tasks`/`operation_task_logs` 和“运维 → 任务”的日志/SSE，无新数据库表、迁移或外部队列。任务类型为 `node_recover`，用 PostgreSQL 每节点事务锁串行创建；重复或并发批准返回已有运行任务编号，不重复下发恢复命令。数据库创建失败不会执行任何节点恢复。
- 后台复用既有身份核对、业务封停/到期检查、原生 operation wait、冻结恢复和逐项 ACK；记录容器恢复进度及失败数量。只记录服务端/原生 operation 日志，不申请并不存在的单实例 QEMU 诊断流，不把任务写入 CLI 审计。支持原生可取消操作的停止，停止后不继续启动后续容器。
- 节点安全页面展示最近恢复任务的状态、错误和任务日志链接，运行时禁用重复批准；失败/停止后保留节点未完成清单，可以重新批准。后台进程重启按现有任务机制标记 `interrupted`；不自动重放管理员批准，需管理员确认后重试，节点仍保存未 ACK 的清单。
- 验证：`test-node-security-async.ts` 阻塞模拟容器启动，确认 HTTP 已返回 202；覆盖并发去重、权限/参数、进度、失败重试、持久化失败无副作用及重启中断。复核既有任务日志/停止/SSE、节点恢复及前端守卫；仅修改控制端，不改变 Incus LTS API 或节点二进制。
- 本地验证结果：异步恢复、既有任务日志/取消/SSE、节点恢复及权限用例通过；前后端类型检查、双端 Vue 构建、前端路由/颜色/i18n/产物边界守卫、make check 和差异空白检查通过。定向 ESLint 无错误，保留 TasksView 原有 4 条格式警告。未发布或部署本次调整。
